# Web UI の組み直し（メッセンジャー型・プロジェクトの担当・右腕）設計（#349）

v1（2026-11-14）。前提: `docs/plan/web-ui.md`（W1〜W7）、`web-ui-polish.md`、`unify.md`（U1）、`claude-code-channels.md`（CC9〜CC14）、`docs/design/WEB-UI-GUIDELINES.md`。未マージの取り込み（#342〜#348）と進行状況（#338）の上には載せない（当たる所は §13）。

> 言葉: **確認（コード）** = main 85e173f のコードで確かめたこと。**確認（SDK・probe）** = SDK 0.3.286 の型の説明と、取り込みの設計（takeover.md §1.2）の probe で確かめられていること。**推測** = そう読めるが動かしていないこと。**未確認** = 動かさないと分からないこと（確かめ方は §6.4）。この設計のために利用枠を使う実測はしていない。

## 0. 目的と結論

**何のために**: 今の Web UI は VS Code 風（アクティビティ・サイドバー・タブ・パネル）で、オーナーは「PC でもスマホでも使い慣れた気がしない」。種類（セッション・Claude Code）を選ばされ、自分の番（許可・質問）を探している。使い慣れたメッセンジャーの形にし、**開いた瞬間に「自分の番」が分かり、頼む相手は 2 人（話題の担当・右腕）だけ**にする。

**結論**
- 画面は 3 列: 列 1「あなたの番 / プロジェクト > 話題 / General」、列 2 選んだ話題の会話、列 3 右腕（PC は常駐・畳める。スマホは下のボタンと話題の見出しから）。
- 一覧は **`GET /api/topics` 1 本**にまとめる（セッション・プロジェクトのセッション・Claude Code を同じ行の形に）。「あなたの番」は **答えないと止まるものだけ**を数える。
- **右腕 = 既定の人格の #inbox**（軽いモードのまま）。足すのは `session_open` の `project`・`text`、新しいツール `topic_list`・`topic_move`、システムプロンプトの数行。**1 つの PR・1 回の再起動にまとめる**（全セッションで 1 回キャッシュが外れる）。
- **General = `SELF_AGENT_WORKSPACE_DIR` の直下のディレクトリ 1 つ**（既定の名前 `General`）。右腕と Web から始める「場所を決めていない話題」は General のプロジェクトのセッションにする。軽いモードは畳まない。
- **付け替えは「要点を引き継いで、新しい場所の新しい会話で続ける」**（/renew の仕組みの流用）。画面の履歴とチャンネルは同じまま。記録を写して逐語で続ける形は未確認が多いので後（§6）。
- Discord 側は組み直さない（1 チャンネル = 1 セッションのまま。`/move` と topic の書き換えだけ足す）。
- 新しい殻は **別の入口のファイルを並べて置き、最後の段で入れ替える**（env の旗は作らない）。段は M0〜M9（§11）。外部サービスは足さない（運用コスト 0 円。増えるのは General の話題のトークン。§5）。

### 1.2 確認（SDK・probe）

- `cwd`・`resume`・`forkSession` は別々の Options。`getSessionMessages`・`forkSession()` は `dir` を省くと全プロジェクトの記録を探す（SDK の型の説明）。
- `snapshot: true` の会話は、resume のたびに**記録した**システムプロンプト（始めたときの cwd・git の節を含む）をそのまま送る。変わるのは圧縮か新しい会話のときだけ（SDK の型の説明・takeover P6）。
- 記録を Bot 側の同じ名前の場所へ写せば、同じ session_id で resume できる（takeover P3）。記録が無ければ `No conversation found`（P2）。

### 1.3 推測・未確認

- **推測**: `sessions.project_dir` だけを書き換えると、次のターンは別の場所の記録を探して F3 に落ちる（会話は黙って題名だけから始め直しになる）。だから付け替えは明示の手順にする。
- **未確認**（§6.4）: 別の cwd の名前の場所へ記録を写して resume できるか／軽いモードの記録をプロジェクトのセッションとして resume できるか（プロンプトの型・ツールの集合が違う）／resume の後のシステムプロンプトに残る古い cwd がどう働くか／General の話題の 1 ターンのトークン。

## 3. 話題の一覧と「あなたの番」

### 3.1 `GET /api/topics`

今の 2 本（F8）を、サーバー側で 1 つの形にして返す。判定は純関数 `src/app/topics.ts` に置き、Web（`web/routes/topics.ts`）と右腕のツール `topic_list`（§4）が同じ結果を使う。今の `/api/channels`・`/api/cc/sessions` は消さない（会話のタブ・古い殻が使う）。

```
{ turns: 2,
  groups: [ { key: "p:self-agent", kind: "project" | "general" | "other", name, turns, running, hasTopics } ],
  topics: [ { id: "ch:<channelId>" | "cc:<sessionId>", title, group, place: { dir | null }, origin: "session" | "project" | "cc",
              mark: "turn" | "running" | "unread" | null,
              turn: { kind: "permission" | "question" | "waiting" | "confirm", summary, since, expiresAt } | null,
              state, last: { id, at, kind }, movable: true | { reason }, link } ] }
```

- **id**: Discord のチャンネルがあれば `ch:`、無い Claude Code のセッションは `cc:`。Claude Code のチャンネルは今も Web では `ch:` で開く（CC14）ので、取り込み（#341。チャンネルがその場でプロジェクトのセッションに変わる）の後も id は変わらない。
- **場所の決め方**: セッションは `project_dir`（General の名前なら群 general）／軽いセッション（`project_dir` なし）は `place.dir = null` で群 general／Claude Code は cwd が workspace の直下の名前かその下ならそのプロジェクト（新しい純関数 `projectOf(cwd, workspace)` を `cc/labels.ts` に足す）、外なら群 other「ほかの場所」。#tasks と人格の入口は群 general の末尾に固定（`movable` は理由つきの不可）。右腕（#inbox）は一覧に出さない。
- **並び**: 群はプロジェクト（話題のあるものを上、名前順）→ General → ほかの場所。話題の無いプロジェクトは「ほかのプロジェクト（n）」に畳む。群の中は あなたの番 → 作業中 → 最後の活動の新しい順。完了は群ごとに「完了（n）」に畳み、開くまで返さない（`?done=<group>`）。
- 足した人格のセッションも同じ群に出し、行に人格の名前を添える（今の一覧のバッジと同じ。行に `persona` を持たせる）。

### 3.2 「あなたの番」の数え方

**オーナーが答えるまで先へ進まないもの**だけ。数は「あなたの番のある話題の数」1 つ（列 1 の先頭・スマホの下のボタン・ホーム画面のバッジが同じ数）。

| 数える | 元 |
|---|---|
| 許可の要求（保留中） | `cc_permissions` の pending（origin hook・sdk の両方） |
| 質問（AskUserQuestion） | 同じ表の `question_input` のある行（U2 が SDK の質問をここに入れれば、そのまま数に入る） |
| 判断待ち（上の行が無い Claude Code の needs_input） | `cc_sessions.state` |
| 確認の札（/close の確認・付け替えの確認・右腕の cc_send / cc_start の確認） | `sessions.state`・`topic_moves`（§6）・`cc_starts`・`cc_sends` の awaiting_confirm |

数えない: 返事が来た（未読の点）／待ち・完了の話題／GitHub の赤（「ほか」の数）／リマインダー。並びは期限（`expiresAt`）の近い順、無ければ古い順。確認の札で右腕のチャンネルに出ているものは、行の題名を「右腕」として列 1 の「あなたの番」に出す（押すと右腕が開く）。

### 3.3 既読

**サーバーに持つ**（今は端末ごとの localStorage で、スマホで読んでも PC で未読のまま）。表 `topic_reads(topic_id, last_read_id, updated_at)`、`POST /api/topics/<id>/read {lastId}`（大きい方だけを採る）。未読 = `last.id > last_read_id` かつ最後の行がオーナーの発言でない。Discord で読んだことは分からない（Discord に送った発言の行で既読を進めるだけ）。移行は、初回に localStorage の値を 1 度だけ送る。

### 3.4 描き方（不具合 1 の根）

一覧は行を key（topic の id）で差し替え、入れ物を作り直さない。スクロール位置・開いた群・フォーカスを保つ。polling は今の間隔のまま（あなたの番があるときだけ 10 秒）。SSE は足さない。

## 4. 右腕

**実体**: 既定の人格の #inbox（軽いモード・今の入れ替えの仕組み・今のツール）。新しい会話の型・プロセス・モデルは足さない。

**「サブエージェントは使わない」に当たらない理由**: 右腕が渡す先は別のチャンネルの別のセッションで、履歴が見え、オーナーが直接話せる。右腕は結果を待たない・受け取らない（知るのは `topic_list` の状態だけ）。右腕の文脈に担当の作業は流れ込まない。今の `session_open` と同じ線の上にある。

| 足すもの | 中身 |
|---|---|
| `session_open` に `project`（任意）と `text`（任意） | `project` が workspace の一覧にあればそのプロジェクトのセッション、無い・省略なら General（§5）。`text` があれば作った後に `submitText` と同じ経路で最初の 1 ターンを始める（発言の出どころは「右腕から」と仕切りに残す）。返す値にチャンネルの ID を含め、右腕は返事に `<#ID>` を書く → Web が札に描く |
| `topic_list` | §3.1 と同じ結果を短い行で（30 件まで。あなたの番 → 作業中 → 新しい順）。「いま動いてるのは？」に答える元 |
| `topic_move` | `{topic, place}`。**確認の札 [変える][このまま] を出すだけ**（§6）。#inbox からは任意の話題、セッションの中からは自分の話題だけ |
| システムプロンプトの数行 | 「頼まれごとは、場所が分かればそのプロジェクトの担当に、分からなければ General に渡す。迷ったら訊かずに General で始め、後で場所を変えられると添える。一覧を訊かれたら topic_list」 |

- **キャッシュの規則**: ツールの集合は全セッション共通のまま（場面で使えないときは今と同じく処理側が `not_available` を返す）。ツールの定義 3 つとシステムプロンプトの変更は **段 M6 の 1 PR・1 回の再起動**に入れる（全セッションの次のターンで 1 回外れる。CLAUDE.md の規則に 1 行足す）。プロジェクトのセッションも同じ MCP サーバーのツールを持つ（確認: `agent/project-profile.ts` の `allowedTools`）ので、足した定義はそこにも見える。`session_open` は今と同じく #inbox・人格の入口の外では `not_available`、`topic_move` は自分の話題だけ。
- **歯止め**: `session_open` の「15 分の間隔」をやめ、「1 ターンに 1 件・1 日の上限（今の `autoSessionPerDay`）」にする（続けて 2 つ頼むのは普通の使い方）。予約した依頼からは今と同じく不可。
- **確認のボタン（推薦）**: 新しい話題を始めるのは**確認なし**（戻せる。中の危ない作業は担当の許可のカードが止める）。`cc_send`・`cc_start` は**確認を残す**（端末のペインに貼るので取り消せない）。付け替えは確認の札。既にある話題への代筆（右腕が別の話題に送る）は作らない: 右腕は札で案内し、オーナーがそこに打つ。
- **Web の右腕の枠**: 列 3 は #inbox の会話そのもの（今の `chat.js`）。見ている話題があるとき、右腕への発言の先頭に「（いま見ている話題: <題名>）」を 1 行添える（Web だけ。履歴にもその形で残る）。

## 5. General

### 5.1 置き場所

`SELF_AGENT_WORKSPACE_DIR` の直下に 1 つ。名前は新しい変数 `SELF_AGENT_GENERAL_DIR`（既定 `General`）。無ければ起動時に作る（workspace が無い・`SELF_AGENT_CC` が無効なら作らない）。理由: `projectDir()` の検査と秘密の守り（F9）を 1 行も変えずに使える・端末の Claude Code からも同じ場所として開ける・付け替えの相手として他のプロジェクトと同じ扱いになる。`listProjects()` の一覧からは除き、群 general として出す。

### 5.2 軽いモードとの関係

| 案 | 中身 | 決定 6 | 当たる所 | 実装 | 評価 |
|---|---|---|---|---|---|

## 6. プロジェクトの付け替え

### 6.1 何が難しいか

F1・F2 と §1.2 のとおり、場所を変えると (a) 記録を探す場所が変わる、(b) `snapshot: true` の会話は古い場所を書いたシステムプロンプトを送り続ける、(c) 軽い ↔ プロジェクトはプロンプトの型とツールの集合ごと変わる。何もしなければ F3 で会話が黙って消える。

### 6.2 案の比較

| 案 | 中身 | 会話の中身 | 確かさ | 新しい場所の正しさ | 実装 / 運用 | 評価 |
|---|---|---|---|---|---|---|
| A | 記録を新しい場所の名前へ写し、同じ session_id で resume | ◎ 逐語 | △ 未確認が 3 つ（§1.3）。軽い ↔ プロジェクトは別の手当てが要る | ✗ 記録したシステムプロンプトに古い cwd が残り、前の場所を触る恐れ | M / 記録が 2 か所に残る | △ |
| **B** | **要点の書き付けを作り、新しい場所の新しい SDK セッションで続ける（/renew の流用）** | ○ 要点（画面の履歴は全部残る） | ◎ 今ある仕組み（F4）だけ | ◎ 新しい場所の CLAUDE.md・skills・cwd で始まる。どの向きも同じ手順 | S〜M / 要約の 1 ターン分のトークン | **◎** |
| C | `forkSession` で分けて新しい場所へ | ◎ | △ A と同じ未確認 | ✗ A と同じ | M / 記録が 2 つ | ✗ |

**決定（推薦）: B で始める。** A は §6.4 の probe で確かめられたら、同じ入口の裏で「逐語で続ける」に差し替えられる（画面・API は変わらない）。モックの文「ここまでの会話を持ったまま、作業する場所だけが変わります」は、B では言い過ぎなので「**会話の記録はこのまま残り、担当には要点を引き継ぎます。あとで戻せます**」にする（未決 1）。

### 6.3 手順（B）

1. 入口: 見出しの「場所 ∨」（`POST /api/topics/<id>/place {place}`）・Discord の `/move place:<名前>`・右腕か担当の `topic_move`（確認の札 → [変える]）。選べるのは General とプロジェクトの一覧だけ（「場所 なし」に戻す口は作らない）。
2. 断るとき（理由の文を出す）: 実行中・許可待ち・/close の途中／足した人格のセッション／端末の Claude Code のセッション（「取り込んでから変えられます」。#341 の後）／同じ場所／一覧に無い名前。
3. そのチャンネルの待ち行列で直列に: **今の場所の runner で要約のターン**（/renew と同じ制限 = 書く・動かすツールを外す。書き付けは 4,000 字まで。「決めたこと・途中の作業・触ったファイル・次にすること」）→ `sessions.project_dir` を更新し `permission_mode` を default に戻す → SDK セッションを捨てる → seed を置く（見出しは今の `RENEWED_SEED_HEADER` のまま。本文の先頭に「作業する場所は <新> に変わりました（前は <旧>）」の 1 行。**システムプロンプトは変えない**）→ 履歴に仕切り「場所を <旧> から <新> に変えました」→ Discord の topic を書き換える（F11）。
4. 要約のターンが失敗したら何も変えない（場所も会話も元のまま。知らせを 1 行）。途中で落ちたら起動時に `topic_moves` の行を見て、場所を変える前なら取り消し、変えた後なら残りを流し直す。
5. 戻す: 同じ手順をもう一度（直前の場所を `topic_moves` に持ち、札に [戻す]）。前の SDK セッションへは戻らない。
6. ファイルは動かさない（前の場所で作ったブランチ・変更はそこに残る。仕切りの下に 1 行で知らせる）。軽いセッションが project_open で作ったページも元の置き場に残る。

DB: `topic_moves(id, channel_id, from_dir, to_dir, state: proposed | running | done | cancelled | failed, by, note, created_at, done_at)`。番号はマージのときの空きで決める（§13）。

### 6.4 未確認の確かめ方（A に進むとき。利用枠を使うのでオーナーの許可で 1 回だけ）

取り込みの probe と同じやり方: 一時の `CLAUDE_CONFIG_DIR` と一時のディレクトリ 2 つ（P・Q）で、(1) P で 1 ターン → 記録を Q の名前の場所へ写して cwd Q で resume できるか、(2) そのとき「今の作業ディレクトリは？」に何と答え、Write がどちらに書くか、(3) 軽いモードの形（custom・`snapshot: false`）で始めた記録を preset・`snapshot: true` で resume できるか。3 つとも通り、(2) が新しい場所なら A を足す。

## 7. Discord 側

**Web だけ組み直す。** Discord は 1 チャンネル = 1 セッション・状態のカテゴリ（進行中・待ち・完了・Claude Code）のまま。足すのは `/move`（§6.3）、確認の札のボタン、topic の書き換えだけ。

困ること（受け入れる）: (1) 地図が 2 つになる（Web はプロジェクトで束ね、Discord は状態で束ねる）。topic に場所を書くので、Discord でも場所は分かる。(2) Discord には「あなたの番」の一覧が無い（今と同じ。許可・質問はそのチャンネルに出て通知で気づく）。(3) Discord の右腕は #inbox そのもの（札は `<#ID>` のリンク）。(4) Discord の `/new`（project 省略）は軽いモードのまま（未決 2）。プロジェクトごとのカテゴリへの組み替えは、チャンネルの移動が多く、状態のカテゴリ（/wait・/close）と両立しないので行わない。

## 14. リスク

1. **M3 の `chat.js`（1 画面に会話 1 つの前提）**: 直す量が読めない。M3 の最初に前提の数を数え、大きければ「列 3 は右腕専用の小さい描画」に倒す（その判断は実装の担当がレビューに出す）。
2. **B の要約の質**: 長い作業の途中で付け替えると細部が落ちる。画面の履歴は残るが、読めるのはオーナーだけで、新しい担当は読めない。書き付けの上限 4,000 字と、付け替えの札の注意の 1 行で受ける。足りなければ §6.4 の A。
3. **右腕の取り違え**: 違うプロジェクトで始める。確認なしにした代わり、札に場所を必ず出し、付け替えを 2 タップにする。
4. **General の重さ**: §5.4。重ければ、General だけ `settingSources` を絞る（別の段）。
5. **入口が 2 つある期間**: M2〜M8 の間、直しを両方に入れる手間。期間を短くする（M2 から M8 までを続けて積む）。
