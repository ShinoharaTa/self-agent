## 3. 優先度マトリクス

### 3.1 評価基準

**影響度 (Impact)**: ユーザー体験、システム安定性、将来の開発効率への影響
- 5: ブロッカー (これなしでは先に進めない)
- 4: 高影響 (ユーザー価値が大きい、または他の機能の前提)
- 3: 中影響 (あると便利、運用改善)
- 2: 低影響 (nice-to-have)
- 1: 最低 (将来的に検討)

**実装コスト (Cost)**: 開発工数、技術的複雑さ、リスク
- 5: 非常に大 (2週間以上、新技術導入、外部依存大)
- 4: 大 (1-2週間、設計変更必要)
- 3: 中 (3-5日、既存パターンで対応可能)
- 2: 小 (1-2日)
- 1: 極小 (数時間)

## 5. Phase 1.5 (現在のコードの安定化) 推奨スコープ

現在Phase 1のコア基盤は一通りのスケルトンが実装されているが、設計と実装の乖離、テスト未実施、エラーハンドリングの不統一がある。次のPhaseに進む前にこれらを解消すべき。

### 5.1 必須タスク
1. **R-12**: Agent traitに`init()`, `tick()`, `shutdown()`を追加し、ARCHITECTURE.mdの設計に合わせる
2. **R-13**: Message構造体にUUID, timestamp, correlation_idを追加
3. **R-24**: main.rsの`abort()`をgraceful shutdownに置き換え
4. **R-15/R-30**: core, storage, task-managerのユニットテスト + cargo testの通過確認
5. **R-17**: coreクレートのエラー型をthiserrorで定義

### 5.2 推奨タスク
6. workspace Cargo.tomlのmembers更新 (llm-client, config, task-managerの追加)
7. `cargo check --workspace` の通過確認
8. Orchestratorのルーティングロジックの充実化
9. ChatBotからのE2Eフロー確認 (メンション -> タスク登録)
